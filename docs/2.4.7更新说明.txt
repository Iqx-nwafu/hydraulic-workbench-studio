有压管网瞬态水力仿真平台 2.4.7
发布日期：2026-11-02

一、新增功能
1. 科研命令行无界面 API 升级到 1.1，轮灌指标与科研三目标口径对齐：simulate 新增 head_sampling（"step_start"：每个灌水时段开始取一次水头，事件后重取）和 pressure_weighting（"segment"：分段等权，标准差按 ddof = 1）两个研究口径选项；irrigation_metrics 新增压力 / 流速 / 不可行分段违反比例与 constraint_violation；新增 plan_objectives 直接返回三目标（100 − 供水达成率、平均缺水量、100 − 压力均匀度）。两个选项都取研究口径时，三目标和约束违反度与科研代码一致到浮点舍入（100 组水头 × 原方案与随机方案，最大差 3e-14）。场景 JSON 和蒙特卡洛配置里也可以写这两个选项；不写时与 API 1.0 结果完全相同。说明见 docs/headless_api.md。
2. 无界面 API 1.2 新增 optimize_exact：给出科研轮灌问题（每个出水口开一次、固定人数分组、每组时长相同、恒定水头）在压力均匀度上的已证明最优方案和最优性上界，可直接作为 NSGA-II 等进化算法的最优参照。方法是枚举全部可行组，再对方案均值做分支定界：宽区间用 LP 松弛定界，窄区间解集合划分 MILP，界都来自已求解的松弛；可行方案由随机构造加局部搜索给出。科研网络缩减到 24、36 个灌水器时分别约 40 s、12–18 min 证明最优；48 个时 1 h 内给出与最优相差不超过 0.11 个百分点的方案。结果可以直接交给 simulate 复核。
3. 菜单栏“帮助”右侧新增“API”按钮，打开“科研接口（API）”窗口，在客户端里直接调用无界面研究 API，不必另装命令行工具。“本机计算”页选择规划 JSON（文件、“监测布设与轮灌”页当前规划或示例管网）后，一键完成管网概况、轮灌组稳态评估、时间轴仿真、蒙特卡洛和精确最优轮灌五类计算；缺少轮灌组、情景或蒙特卡洛配置文件时，按规划中的出水口自动生成模板。窗口与命令行使用同一套参数解析和计算函数，输出文件与 manifest 和命令行逐项相同，可直接作为论文复现材料。“模型设置”页统一覆盖摩阻律、局部损失系数、压力与流速限值等九项模型选项，并设置蒙特卡洛并行进程数、缓存规模和输出根目录，保存后长期生效。“命令行与脚本”页一键复制与当前设置完全等价的命令行和 Python 代码，界面里调好的计算可以直接放进批处理；也可在这里用当前账户为本机科研命令行工具授权。
4. 科研命令行新增 api optimize-exact 命令：直接输出精确最优轮灌方案（plan.json、schedule.csv）与记录最优性上界和间隙的 manifest，与 Python 调用 optimize_exact 结果一致。
5. 平台按功能拆分为 19 个模块，每个模块有独立的版本号，包括界面外壳与图标、计算内核、单管计算、网络工况、拓扑与图纸识别、轮灌设计与优化、科研接口等。“帮助 → 关于 → 模块版本”列出每个模块的版本和内容，运行日志同时记录各模块版本，反馈的问题可以直接对应到具体模块和版本。
6. 软件更新只下载有变化的文件：检查更新时，版本说明最前面列出本次更新的模块和版本变化；下载前软件先比对本机文件，只取回内容不同的文件，逐个校验 SHA-256 后，由更新器与未变的文件组装成新版本，替换、启动检查和失败自动恢复与完整更新包相同，用户配置和 outputs 目录照常保留。只改两个界面文件的更新需要下载约 0.14 MB，完整更新包超过 300 MB；比对和下载通常只需几秒。变化的文件超过完整包的 60% 时，软件自动改下完整更新包。

二、改进与修复
1. 用户须知“数据与隐私”和 AI 小助手首次使用说明写明服务商所在地：DeepSeek、Kimi、千问为境内服务商，GPT（OpenAI）为境外服务商，管理员选用 GPT 时，提问内容会传输到境外服务器处理。英文版须知补上此前缺少的“AI 小助手”和“账户联系方式与找回密码”两段。
2. 英文界面补齐 471 条提示，涉及监测布设与轮灌、全局优化、传感器认证和科研命令行账户校验，英文界面不再出现中英混排。
3. 网络计算统一使用“网络工况”一词：“文件 → 打开网络工况… / 保存网络工况”、工况设置页标题、状态栏与提示文字中的“管网工况”都改为“网络工况”，与“网络计算”页名一致。功能和文件格式不变。
4. 修复：输出目录与软件安装目录不在同一个盘时（例如工程放在 D: 盘、软件装在 C: 盘），图纸识别导入管网会报错 “path is on mount 'D:', start on mount 'C:'”。现在这种情况下工况文件里改记 EPANET 组件的绝对路径，导入正常完成。
5. AI 小助手知识库与新界面逐条对齐：知识库引号中的每个按钮、菜单和页面名称都会自动核对是否存在于当前界面，旧名称会注明“（2.4.6 及更早为…）”。同时更正单管模型一章的按钮说明：运行按钮始终显示为“开始 MOC 计算”，点击后按所选求解方法（MOC 或 FVM）计算。
6. 修复：还没有打开网络工况时，通过“文件 → 导入管网图纸”或“选择图纸并识别…”识别图纸，在复核窗口点“确认并导入拓扑”后，识别（含复核中修改）的拓扑没有进入“网络计算 / 拓扑参数”页，只提示“已取消替换管网”。现在会直接生成网络工况并打开到拓扑参数页；已打开网络工况时，仍先保存其未保存的设置再替换。
7. 主界面细节打磨：右上角去掉与账户菜单重复的“设置”按钮，AI 小助手与反馈按钮随之右移；顶栏图标、头像、校徽与院徽按 100%–400% 每档显示缩放各备一张原尺寸图，高分屏上不再发虚，校徽院徽同时略微放大；项目浏览器的“单管模型”“网络计算”单击即可展开或收起子页，收起时所在分组高亮；左下角“设置”“日志”的图标与文字对齐；工况设置和计算设置的输入框统一宽度，单位单独成列对齐；“关于”和用户须知改为分节排版，正文两端对齐、首行缩进两字。
8. 多显示器自适应：窗口按所在显示器的可用区域打开，笔记本或 125% 以上缩放的 1080p 屏直接最大化，更大的屏幕按比例居中；拖到缩放比例不同的另一块屏幕时按新屏幕重新排版，放不下时自动收拢。结果输出、单管结果浏览等较高的页面改为页内滚动，窗口不会再被撑得比屏幕还高。

三、兼容说明
1. 升级到 2.4.7 后首次登录需重新勾选同意《用户须知与隐私说明》（版本 2026-10-30.1）；模型训练授权版本不变，已有授权继续有效。
2. 安装包不再附带 tkinter / Tcl / Tk 运行库（新界面完全基于 Qt，不使用它们），打包时会自动核对，确保它们没有被带进安装包。
3. 审批中心源码删除了 56 个从不加载的旧模块（2.3.0 时整包复制的旧 Tk 工作台界面和客户端求解模块），运行行为、数据库和接口都没有变化，2.4.5 / 2.4.6 客户端照常使用。在源码模式下需要运行一次 sync-local，再重启审批中心生效，被删除的文件会移到备份目录。
4. 无界面 API 1.2 向后兼容 1.0 / 1.1：已有脚本、场景 JSON 和 CSV 列名都不用改动。
5. 分文件更新从 2.4.7 开始生效：2.4.6 及更早版本升级到 2.4.7 时下载完整更新包，2.4.7 之后的每次更新只下载有变化的文件。这一功能需要审批中心同为 2.4.7 及以上版本，审批中心未升级时客户端照常下载完整更新包。
