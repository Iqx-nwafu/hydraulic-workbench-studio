# 有压管网瞬态水力仿真平台 · 2.4.8

面向城市供水与灌溉输配水的一维瞬态水力分析平台，支持单管、分支及环状管网的特征线法（MOC）和有限体积法（FVM）。从参数建模、图纸识别与拓扑复核，到瞬态计算、真实纵断面与压力校核、关阀方案比较、轮灌规划与监测布设和结果报告，在同一工作台内完成分析；平台的稳态水力模型还可以通过无界面研究 API 和科研命令行工具直接接入研究代码。

**2.4.8 新增“闸门监测”：接入闸门厂家的闸控平台实时查看渠道上的每一座闸门，渠道三维视图中点闸门即看数据，导入现场雷达水位计、流量计数据，按放水过程给出渠段输水效率及其不确定度。审批服务搬到云服务器全天在线，填写邮箱验证码注册即刻开通；计算资源按本机核数与空闲内存自动分配，4 核电脑上 6 个方案的批量对比快 2.8 倍。**

本仓库提供 **Windows 客户端、科研命令行工具、版本说明和使用文档，不公开软件源代码**。普通用户无需安装 Python 或配置开发环境。

## 2.4.8 新增

1. **闸门监测**：项目浏览器“监测布设与轮灌”下方新增一级项目“闸门监测”，接入闸门厂家的闸控平台，实时查看渠道上的每一座闸门。左栏按渠道列出闸门的在线状态、开度和最后上报时间，有报警时“闸门监测”条目后面显示报警数，在任何页面都能看到；卡片显示开度、供电（电压、信号强度、柜温）、运动状态与控制模式；趋势图可选 6 小时、24 小时、7 天或自定义时段，时间轴在本机时间与北京时间（现场）之间切换，缺测区间灰显断开、不补零，可导出 CSV；“事件与报警”“操作记录”“闸门配置”页签保留完整历史。数据保存在本机，首次连接立即取回最近 6 小时，再在后台补齐近 30 天或全部 2 年历史。连接信息加密保存，首次连接核对厂家服务器证书指纹，之后只信任这张证书；软件只发查询请求，不下发任何闸门指令。
2. **渠道三维**：闸门监测页顶部的“渠道三维”展示实验站梯形渠的三维模型（主渠两道节制闸和分水口支渠闸），每座闸门挂着名称、开度、在线状态和最后上报时间，闸板随实时开度升降；点标签或闸门本体即选中这座闸门，下方切换到它的数据，与左栏选中互相跟随。“实时”可旋转、平移、缩放视角，“固定”锁定总览视角，只在开度或选中变化时渲染一帧，空闲 5 秒释放显卡资源；没有可用显卡时自动改用 CPU 渲染。
3. **雷达测点接入与渠段水量平衡**：渠道上的雷达水位计、雷达流量计在“雷达测点表”里登记渠道、位置和关联闸门后，闸门卡片直接显示闸前、闸后水深，瞬时流量和今日水量。“导入测点数据…”一步导入现场工控机导出的 xlsx，不连厂家平台也能用，重复导入自动去重。同一渠道有渠首、末端两台流量计时，“渠段水量平衡”按放水过程或按日给出渠首水量、末端水量、渠段损失和输水效率：两端水量取累计水量增量，缺测时段用瞬时流量积分补齐并计入数据完整度，自动估计水流到达末端的滞后并对齐两条流量曲线，按两台流量计各自的误差独立合成输水效率的 ± 不确定度。
4. **注册即刻开通，账户变更立即生效**：注册时同时填写手机号和邮箱，填入发到邮箱的 6 位验证码后提交，账户立即开通并显示使用期限，可直接登录。修改密码、更改账户名、绑定或修改手机号立即生效，修改邮箱填写新邮箱的验证码后立即生效；每个手机号、每个邮箱只对应一个账户。

6. **计算资源自动分配**：新增“设置 → 计算资源”，默认按任务数、逻辑核数 − 1（留一个核保证界面流畅）和空闲内存 70% 所能容纳的进程数三者中的最小值分配计算进程，也可手动指定。管网批量方案对比、单管参数网格校准改为多进程并行，结果与逐个计算逐字节一致，4 核电脑上 6 个方案的对比由 36.9 s 缩短到 13.1 s；监测布设误差校核和蒙特卡洛同样按此分配。

## 科研接口

平台把用于轮灌规划的稳态水力模型开放为可编程接口（2.4.5 起），2.4.7 起客户端菜单栏的“API”按钮可在界面里直接调用同一套接口。研究代码不再需要在界面里逐组点击，也不需要自行重写水力计算，就能得到与平台规划器同一口径、可复现、可归档的结果。

### 无界面研究 API（`hydraulic_moc.api`，API 1.2）

| 能力 | 说明 |
| --- | --- |
| 稳态评估 | 树状管网矩阵精确求解，环状管网全局梯度法迭代；单组或成批评估轮灌组；H-W、D-W 与固定 Darcy 系数可逐管混用，逐管局部损失系数与运动黏度 |
| 故障隔离 | 节点、管段、出水口三类故障按连通性自动隔离：树状管网隔离故障点下游子树，环状管网自动经其他路径改道供水 |
| 时间轴仿真 | 轮灌计划、时变水源水头（阶梯、线性、常量）、故障与恢复事件；在每个事件后调用外部重规划钩子，可接入 NSGA-II 等任意优化器 |
| 蒙特卡洛 | 固定种子、逐场景独立可复现（第 i 个场景由 `[seed, i]` 决定），多进程并行，结果与进程数和执行顺序无关 |
| 精确缓存 | 按“开启出水口集合 + 关闭管段集合”精确缓存，水源水头只做整体平移，大规模组合搜索显著提速且不引入任何近似 |
| 研究口径（1.1） | `head_sampling`、`pressure_weighting` 与科研三目标口径对齐，`plan_objectives` 直接返回三目标，与科研代码一致到 3e-14 |
| 精确最优轮灌（1.2） | `optimize_exact` 枚举全部可行组，对方案均值分支定界（LP 松弛 + 集合划分 MILP），给出压力均匀度的已证明最优方案与有效上界 |
| 结果归档 | 每份结果附 `api_version`、`platform_version`、输入 JSON 的 SHA-256、`network_digest`、`model_digest` 与全部生效选项 |

指标包括开启出水口最低/平均压力、各类约束违反量与计数、可行性，以及时间轴仿真的供水达标率、亏缺量、压力均匀度、可行时间占比等；目标函数由研究自行用这些指标组合。

### 科研命令行工具

发行版附带独立的 **科研命令行工具**（`HydraulicWorkbenchResearchCLI-2.4.8-Windows-x64.zip`），解压即用，不需要 Python 环境，也不依赖客户端是否安装。首次使用先用已获批的平台账户登录一次，授权有效期内（最长 14 天，且不晚于账户使用期限）计算不需要联网。

```powershell
hydraulic-moc login                                                                 # 平台账户登录（脚本可用 --password-stdin）
hydraulic-moc status                                                                # 查看登录账户与授权到期时间
hydraulic-moc api describe    --project net.json                                   # 管网概况与最终生效的模型选项
hydraulic-moc api evaluate    --project net.json --groups groups.jsonl --output out.jsonl [--detail]
hydraulic-moc api simulate    --project net.json --scenario scenario.json --output sim/
hydraulic-moc api monte-carlo --project net.json --config mc.json --output mc/ --workers auto
hydraulic-moc api optimize-exact --project net.json --group-size 4 --step-h 4 --time-limit 600 --output exact/   # 精确最优轮灌
hydraulic-moc irrigation-eval --project net.json ...                                # 轮灌组稳态评估器
hydraulic-moc logout                                                                # 删除本机登录记录
```

| 命令 | 输入 | 输出 |
| --- | --- | --- |
| `evaluate` | JSONL，每行 `{"id", "open": [...], "source_head_m"?, "unavailable"?, "faults"?}` | `.jsonl`（`--detail` 含逐节点、逐管段、逐出水口的值）或 `.csv`，另写 `<名>.manifest.json` |
| `simulate` | `{"schedule": [...], "head"?, "events"?, "horizon_h"?}` | `segments.csv`、`outlets.csv`、`summary.json` |
| `monte-carlo` | 场景规格 + `"scenarios"` + `"schedule"` | `scenarios.csv`、`events.csv`、`manifest.json` |
| `optimize-exact` | 只需 `--project`；`--group-size`、`--step-h`、`--time-limit`（秒）、`--source-head`、`--seed` | `plan.json`、`schedule.csv`、`manifest.json`（含最优性上界与间隙） |

所有模型选项都可用命令行参数覆盖：`--friction --local-loss-ratio --min-pressure --min-velocity --max-velocity --velocity-scope --max-source-flow --outlet-law --outlet-design-pressure`。未登录或授权无效时，计算命令以退出码 3 结束并说明原因，便于批处理脚本判断。

### 规划 JSON：统一输入

科研接口与桌面端“监测布设与轮灌”共用同一种规划 JSON（`hydraulic-irrigation-planning` v1）：在界面中“保存规划”得到的文件可直接交给接口；接口生成的文件也能在界面中打开。`topology.nodes / pipes` 描述单水源的树状或环状管网，`fields` 的每条记录是一个出水口（设计流量与目标水量），`settings` 保存首部压力、最低压力、流速范围与供水上限。接口专用选项放在 `settings.hydraulic_api` 下，桌面端不受影响。单位固定：长度 m、流量 m³/h（接口结果中带 `_m3_s` 后缀的为 m³/s）、水量 m³、时间 h。

### 研究口径默认值

不带任何选项时即为轮灌研究口径，研究不需要在文件里重复写这些值：

| 选项 | 默认值 |
| --- | --- |
| 摩阻律 | EPANET 2.2 全流态（与平台瞬态求解器一致） |
| 局部损失 | 按沿程损失的 0.1 倍计入（逐管 K 值另外累加） |
| 最低压力水头 / 设计压力 h_d | 11.4 m |
| 流速范围 | 0.3–2.5 m/s，只校核有流量的管段 |
| 出流规则 | `linear_cap`：q_d·clip(p/h_d, 0, 1) |

界面保存的规划 JSON 若自带 `min_pressure_m`、`velocity_scope` 等共用键，则以文件中的值为准；`describe` 会打印最终生效的值，全部选项进入 `model_digest` 随结果一起归档。

### 轮灌组稳态评估器（`irrigation_eval`）

面向轮灌调度研究的轻量评估接口（命令 `hydraulic-moc irrigation-eval`），树状管网、D-W 摩阻，输入灌水器流量与不可用集合，输出逐节点压力、逐管流量流速与可行性，带精确缓存。与无界面 API 在同一口径下 200 组随机组合逐位一致，已有研究代码可以继续沿用。

### 适用范围

接口做稳态和逐段稳态计算，面向轮灌规划、调度优化与可靠性分析；瞬态（水锤）校核请使用平台的 MOC/FVM 求解器。支持单水源、被动管道组成的树状与环状管网，与桌面端规划器的支持范围一致。完整的输入格式、选项、Python 调用方式与稳定性约定见 [无界面研究 API 说明](docs/无界面研究API说明.md)。

## 第一次计算

建议先运行随包示例，熟悉 **“建立模型 → 参数检查 → 求解计算 → 结果分析”**，再输入实际工程数据。

1. 登录后选择 **“文件 → 打开工况…”**，打开随包 `configs/longitudinal_network_test.json`。程序识别为管网工况，进入“网络计算 / 拓扑参数”。
2. 在 **“网络计算 / 工况设置”** 点击 **“真实纵断面与压力限值…”** 查看示例：管段 `P` 长 100 m，在 0、35、100 m 位置的管中心高程分别为 0、20、0 m，默认压力水头限值为 12～36 m。
3. 进入 **“计算设置”**，保留默认 MOC，点击 **“打开计算检查中心”**。查看阻止项及警告，存在阻止项时点“定位并修复”先修正。
4. 点击 **“运行 MOC 全网计算”**，或在网络计算页按 `F5`。计算在后台运行，状态栏显示进度，可点“取消”或按 `Esc`。
5. 完成后自动进入 **“结果输出”**，在 **“纵断面校核”** 页签查看管中心线、最大/最小 HGL 包络及超限区段，点击 35 m 高点查看压力时程，或点“定位最不利位置”。
6. 需要更改输出位置时，在“结果输出”页的“输出目录”点击“更改…”。通过 **“文件 → 保存网络工况”** 保存可再次编辑的工况 JSON。

单管示例：同样用 **“文件 → 打开工况…”** 打开 `configs/longitudinal_single_pipe.json`，程序自动进入单管模型；在单管页点“计算检查中心”后“开始 MOC 计算”（或按 `F5`），完成后自动进入“结果浏览”。完整 CSV 导入、FVM 对照与方案比较步骤见 [纵断面使用示例](docs/LongitudinalReadme.txt)。

示例为人工构造的动态工况。HGL 为测压管水头，压力水头为 `HGL − 管中心高程`。包络记录计算内部步极值，极值可能发生在两个保存帧之间。

### 轮灌与监测布设示例

1. 在左侧项目浏览器点击 **“监测布设与轮灌”**。
2. 点击 **“载入管网 ▾”**，选择随包示例（如“全管通水验证例”）；也可以点 **“从网络计算导入”**，直接使用网络计算中打开的管网。在“输入与约束”和工具栏“约束与误差设置”中核对首部压力、供水上限、最低压力、流速上下限及田块需水量。
3. 点击 **“1 计算轮灌”**，查看各轮开启单元、时长、供水量和压力统计；全部硬约束通过并取得证书后，才能进入下一步。
4. 核对仪表误差、估计容限和验证域后点击 **“2 校核误差并布点”**，在“传感器布设”和“逐轮误差校核”查看所需仪表位置及每轮误差界。图中圆形为压力计、三角形为流量计。
5. 需要同时设计管径时，在“管径与轮灌设计”页启用管径设计，填写“内径与成本目录”，在“计算设置”中选择求解方式后“生成初始方案并联合搜索”，再“选择并冻结”所选方案。
6. 通过“保存规划”保存可再次打开的输入，通过“导出结果”保存方案、布点、误差校核及最优性证书。保存的规划 JSON 可直接作为科研接口的输入。

轮灌结果对应所输入的管网、田块、约束和误差设置；最少传感器数量只针对已冻结的方案和声明的误差域。成本目录中的示范值为相对指数，实际设计请填写真实报价。

### 科研接口示例

1. 解压科研命令行工具，在 PowerShell 中进入该目录，运行 `.\hydraulic-moc.exe login` 用平台账户登录。
2. 运行 `hydraulic-moc api describe --project examples\farm_network.json`，查看管网概况与最终生效的模型选项。
3. 运行 `hydraulic-moc api evaluate --project examples\farm_network.json --groups examples\groups.jsonl --output out.jsonl --detail`，得到每个轮灌组的压力、流量、流速与可行性，以及 `out.manifest.json`。
4. 运行 `hydraulic-moc api simulate --project examples\farm_network.json --scenario examples\scenario.json --output sim\`，得到含故障与恢复的时间轴结果（`segments.csv`、`outlets.csv`、`summary.json`）。
5. 运行 `hydraulic-moc api monte-carlo --project examples\farm_network.json --config examples\monte_carlo.json --output mc\ --workers auto`，得到固定种子、可复现的多场景统计。
6. 运行 `hydraulic-moc api optimize-exact --project examples\farm_network.json --group-size 2 --step-h 4 --output exact\`，不到一秒得到示例管网 8 个出水口两两一组的已证明最优方案（`plan.json`、`schedule.csv`、`manifest.json`）。

把 `examples\farm_network.json` 换成在界面中“保存规划”得到的文件，即可对自己的管网做同样的计算。以上计算也可以在客户端点“API”按钮，在“本机计算”页选“示例管网”直接运行，输出与命令行逐项相同。

## 使用自己的工程数据

| 步骤 | 操作要点 |
| --- | --- |
| 建模 | 选择单管或管网，录入几何、材料、波速、摩阻、初始条件、边界及阀门动作 |
| 图纸导入（可选） | 通过“文件 → 导入管网图纸（PNG/JPG/JPEG/DXF）…”识别，在“识别拓扑校核”窗口复核连接、水源及比例尺，再在“网络计算 / 拓扑参数”补全水力参数 |

| 检查与计算 | 选择适用的 MOC 或 FVM，在计算检查中心核对网格、时间步、输出间隔和资源需求，逐条“定位并修复”阻止项后按 F5 运行 |

纵断面 CSV 表头为 `pipe_id,station_m,centerline_elevation_m`。单管编号固定为 `single`，管网使用实际管段编号；模板位于随包 `data/input/`。

修改工况、剖面或压力限值后需要重新计算。未设置压力限值不代表校核通过；超限区段长度表示统计窗内曾超限位置集合的长度，并非同时超限长度或超限持续时间。

平台用于科研、教学及辅助分析。图纸识别不能替代真实参数测量；本版不求解泵停机、空化、液柱分离或防护设备。出现汽化阈值越界时，单相模型结果不能继续作为有效物理结论。实际工程应用需核验输入数据与模型适用范围。

- **反馈问题**：在线登录后点击顶栏 ✉ 图标提交，截图可直接 `Ctrl+V` 粘贴；也可在本仓库的 [Issues 页面](https://gitee.com/Iqx-nwafu/hydraulic-workbench-studio/issues)提交问题。制作方的回复可在头像菜单“我的反馈与回复…”中查看。

| 常见现象 | 处理方式 |
| --- | --- |
| 注册仍在等待审核 | 2.4.8 起填写邮箱验证码注册即刻开通；未填验证码的申请联系制作方确认，重复提交不会自动开通 |
| 提示手机号或邮箱已被其他账户使用 | 每个手机号、每个邮箱只对应一个账户；换一个，或用“忘记密码？找回密码”找回原账户 |
| 账户停用、未获批准或授权到期 | 联系制作方核实状态或申请续期 |
| 账户服务连接失败 | 检查网络；首次登录需服务可达，已获有效本机授权时程序会尝试离线登录 |
| 忘记密码 | 登录页“忘记密码？找回密码”用注册邮箱收取验证码；未绑定邮箱时联系制作方 |
| 没有收到找回密码验证码 | 检查邮箱垃圾箱；60 秒后可重新获取，每个账户每天最多 5 次 |
| 升级后登录要求重新同意须知 | 《用户须知与隐私说明》已更新，阅读后勾选同意即可，原有授权与数据不受影响 |
| 缺少运行库或识图组件 | 重新下载、核对校验值并完整解压，保留整个程序目录；识图组件状态异常时在“组件详情”中点“重新检查组件” |
| 识图首次启动较慢 | 等待组件加载，查看阶段及状态提示，必要时取消任务 |
| 小助手提示暂不可用或次数已用完 | 确认已在线登录；每天 10 次，次日恢复，也可直接使用“反馈” |
| 联合设计或误差布点耗时较长 | 在“计算设置”中调整时限，状态栏可随时取消；查看证书中的上下界和证明状态 |
| 命令行提示“尚未登录”或授权已到期 | 运行 `hydraulic-moc login` 重新登录；`hydraulic-moc status` 查看授权到期时间 |
| 科研接口报告规划 JSON 无法读取 | 用界面“保存规划”重新导出，或用 `describe` 查看提示的字段；记录不能带多余键 |
| 联系方式修改未生效 | 2.4.8 起手机号立即生效；改邮箱需先获取并填写发到新邮箱的验证码 |
| 闸门显示“离线” | 闸控器没有按周期上报，多为现场太阳能供电或 4G 流量卡问题；点开看“供电”里断线前最后的电压和信号，联系现场或闸门厂家 |
| 闸门监测提示令牌失效或证书指纹不一致 | 向闸门厂家确认令牌是否到期、证书是否更换，在“连接设置”里更换令牌或重新核对指纹 |
| 软件更新提示改为下载完整更新包 | 本机文件与新版差异较大或某个文件未通过校验时，软件自动改下完整更新包，按提示继续即可 |
| 导出失败或文件被占用 | 关闭占用目标文件的程序，检查目标目录写入权限后重试 |

反馈请附软件版本、Windows 版本、复现步骤、错误提示及可公开的最小示例。公开提交的问题中不要附密码、授权缓存、会话信息或未经允许披露的图纸和项目资料；分享日志前请检查其中的个人与项目信息。
